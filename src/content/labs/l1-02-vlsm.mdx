## Objetivos

- Calcular un esquema VLSM a partir de los requisitos de hosts de cada LAN.
- Configurar las interfaces del router con máscaras de distinta longitud.
- Interpretar las rutas conectadas y locales de la tabla de enrutamiento.

## Escenario

Una empresa recibió el bloque **172.16.0.0/24** para su sede. Tiene tres áreas, cada una en su propia LAN conectada
a una interfaz del router R1. Debes diseñar el direccionamiento usando el espacio de la forma más eficiente y dejar
libre el mayor bloque contiguo posible para crecer.

| LAN | Interfaz de R1 | Hosts necesarios |
|---|---|---|
| Ventas | G0/0/0 | 100 |
| Bodega | G0/0/1 | 50 |
| Gerencia | G0/0/2 | 20 |

## Parte 1: Diseñar el esquema

Completa esta tabla en papel **antes** de abrir Packet Tracer. Asigna desde el inicio del bloque, de la LAN más
grande a la más pequeña.

| LAN | Hosts | Prefijo | Red | Primer host | Último host | Broadcast |
|---|---|---|---|---|---|---|
| Ventas | 100 | ? | ? | ? | ? | ? |
| Bodega | 50 | ? | ? | ? | ? | ? |
| Gerencia | 20 | ? | ? | ? | ? | ? |
| Libre | | ? | ? | | | |

Convención de direcciones para este laboratorio:

- La interfaz de R1 usa la **primera** dirección utilizable de cada LAN.
- La PC de cada LAN usa la **última** dirección utilizable.

## Parte 2: Armar la topología

1. Coloca un ISR4331, tres switches 2960 y tres PC como en el diagrama.
2. Conecta todo con cable directo de cobre. Los switches no necesitan configuración en este laboratorio.

## Parte 3: Configurar R1

1. Asigna el nombre **R1** y desactiva la búsqueda DNS.
2. Configura cada interfaz con la primera dirección utilizable de su LAN, la máscara que calculaste y una
   descripción con el nombre del área.
3. Enciende las tres interfaces y guarda la configuración.

## Parte 4: Configurar las PC

Configura cada PC con la última dirección utilizable de su LAN, la máscara correspondiente y la IP de R1 en esa LAN
como gateway.

## Verificación

1. Desde cada PC, haz ping a su gateway.
2. Desde PC-A haz ping a PC-B y a PC-C. El router conoce las tres redes porque están **directamente conectadas**: no
   necesitas rutas estáticas ni protocolos de enrutamiento.
3. Desde PC-A ejecuta `tracert 172.16.0.222`. Debes ver dos saltos:

```text
C:\>tracert 172.16.0.222

Tracing route to 172.16.0.222 over a maximum of 30 hops:

  1   0 ms      0 ms      0 ms      172.16.0.1
  2   0 ms      0 ms      0 ms      172.16.0.222

Trace complete.
```

4. En R1, revisa la tabla de enrutamiento:

```text
R1# show ip route
...
      172.16.0.0/16 is variably subnetted, 6 subnets, 4 masks
C        172.16.0.0/25 is directly connected, GigabitEthernet0/0/0
L        172.16.0.1/32 is directly connected, GigabitEthernet0/0/0
C        172.16.0.128/26 is directly connected, GigabitEthernet0/0/1
L        172.16.0.129/32 is directly connected, GigabitEthernet0/0/1
C        172.16.0.192/27 is directly connected, GigabitEthernet0/0/2
L        172.16.0.193/32 is directly connected, GigabitEthernet0/0/2
```

Fíjate en la línea **variably subnetted, 6 subnets, 4 masks**: tres redes conectadas (C) con tres máscaras distintas,
más tres rutas locales (L) /32, una por cada IP del router. Esa línea es la huella de VLSM.

## Solución

<details class="solucion">
<summary>Ver la configuración de R1</summary>

```text
enable
configure terminal
hostname R1
no ip domain-lookup
interface gigabitethernet0/0/0
 description LAN Ventas
 ip address 172.16.0.1 255.255.255.128
 no shutdown
interface gigabitethernet0/0/1
 description LAN Bodega
 ip address 172.16.0.129 255.255.255.192
 no shutdown
interface gigabitethernet0/0/2
 description LAN Gerencia
 ip address 172.16.0.193 255.255.255.224
 no shutdown
 end
copy running-config startup-config
```

| PC | IP | Máscara | Gateway |
|---|---|---|---|
| PC-A | 172.16.0.126 | 255.255.255.128 | 172.16.0.1 |
| PC-B | 172.16.0.190 | 255.255.255.192 | 172.16.0.129 |
| PC-C | 172.16.0.222 | 255.255.255.224 | 172.16.0.193 |

</details>
