## 1.3.1 Funcionamiento de Telnet

Telnet (puerto TCP 23) envía **todo en texto plano**: el usuario, la contraseña y cada comando. Cualquiera que capture
el tráfico, con Wireshark por ejemplo, lee tus credenciales sin esfuerzo. Por eso ya no se usa para administrar equipos.

## 1.3.2 Funcionamiento de SSH

SSH (*Secure Shell*, puerto TCP 22) hace lo mismo que Telnet, pero **cifra** la sesión y **autentica** al usuario.
Si alguien captura el tráfico, solo ve datos ilegibles.

<div class="duo">

<div>

#### Telnet

- TCP 23
- Texto plano
- Contraseña de línea (`password` + `login`)

</div>

<div>

#### SSH

- TCP 22
- Sesión cifrada
- Usuario y contraseña locales (`login local`) o un servidor AAA

</div>

</div>

## 1.3.3 ¿El switch admite SSH?

Solo las imágenes de IOS **criptográficas** (con `k9` en el nombre) incluyen SSH. Compruébalo:

```text
S1# show version
Cisco IOS Software, C2960 Software (C2960-LANBASEK9-M), Version 15.0(2)SE7
S1# show ip ssh
SSH Disabled - version 1.99
%Please create RSA keys to enable SSH (and of atleast 768 bits for SSH v2).
```

<aside class="ojo">

Para borrar las claves: `crypto key zeroize rsa`. SSH se deshabilita automáticamente.

</aside>

## 1.3.5 Verificar que SSH funciona

Desde una PC (con PuTTY o, en Packet Tracer, el *Command Prompt*):

```text
C:\> ssh -l admin 172.17.99.11
Password:
S1>
```

En el switch:

```text
S1# show ip ssh
SSH Enabled - version 2.0
Authentication timeout: 120 secs; Authentication retries: 3
S1# show ssh
Connection Version Mode Encryption  Hmac         State           Username
0          2.0     IN   aes256-cbc  hmac-sha1    Session started admin
0          2.0     OUT  aes256-cbc  hmac-sha1    Session started admin
```

<aside class="examen">

La lista que hay que saber de memoria: **hostname**, **ip domain-name**, **crypto key generate rsa**, **username … secret**,
**line vty** con **transport input ssh** y **login local**, **ip ssh version 2**.

</aside>
