Los routers y switches de Cisco se configuran desde la línea de comandos de **IOS** (o IOS XE en equipos recientes;
para el CCNA se manejan igual). Vas a pasar mucho tiempo aquí, así que vale la pena moverse con soltura.

## Cómo se accede

- **Consola**: cable de consola (RJ-45 o USB) directo al equipo. Es el acceso de primer día y de emergencia: funciona
  aunque la red esté caída.
- **Remoto por red**: SSH (cifrado) o Telnet (todo en texto plano; solo para laboratorio). Requiere que el equipo
  tenga IP y que las líneas VTY lo permitan.

## Modos de la CLI

```text
Router>                          modo EXEC de usuario: comandos de consulta limitados
Router> enable
Router#                          modo EXEC privilegiado: show, copy, reload, debug
Router# configure terminal
Router(config)#                  configuración global
Router(config)# interface g0/0/0
Router(config-if)#               configuración de una interfaz
Router(config-if)# exit          sube un nivel
Router(config-if)# end           vuelve directo a Router# (también Ctrl+Z)
```

Ayudas que usarás todo el tiempo:

- `?` lista los comandos posibles en ese punto. `sh?` lista lo que empieza por «sh».
- **Tab** completa el comando. Puedes abreviar: `sh ip int br` equivale a `show ip interface brief`.
- `do` ejecuta un comando de EXEC desde el modo de configuración: `do show ip interface brief`.
- `no` delante de un comando lo deshace: `no shutdown`, `no ip address`.

## Dos configuraciones

| | running-config | startup-config |
|---|---|---|
| Dónde vive | RAM | NVRAM |
| Cuándo cambia | Al instante, con cada comando | Solo cuando la guardas |
| Al reiniciar | Se pierde | Se carga como la nueva running-config |

```text
Router# copy running-config startup-config
Router# show running-config
Router# show startup-config
```

## Configuración básica de un equipo

```text
Router(config)# hostname R1
R1(config)# no ip domain-lookup
R1(config)# enable secret Clase#2026
R1(config)# service password-encryption
R1(config)# banner motd #Acceso solo para personal autorizado#
R1(config)# line console 0
R1(config-line)# password Consola#2026
R1(config-line)# login
R1(config-line)# logging synchronous
R1(config-line)# exec-timeout 10 0
```

Qué hace cada línea que no es obvia:

- `no ip domain-lookup` evita que IOS intente resolver por DNS cada palabra que escribes mal.
- `enable secret` protege el modo privilegiado con un **hash**. Si existe, tiene prioridad sobre `enable password`.
- `service password-encryption` oculta las contraseñas que quedan en texto plano con un cifrado **tipo 7**. Solo
  evita que alguien las lea por encima del hombro: el tipo 7 se revierte en segundos.
- `logging synchronous` evita que los mensajes del sistema corten lo que estás escribiendo.

## Dirección IP en routers y switches

Un **router** lleva IP en cada interfaz que conecta a una red. Las interfaces del router vienen apagadas:

```text
R1(config)# interface gigabitethernet0/0/1
R1(config-if)# description Enlace a S1
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# no shutdown
```

Un **switch de capa 2** no enruta: sus puertos no llevan IP. Para administrarlo se crea una interfaz virtual (SVI)
y se le indica a qué router enviar el tráfico hacia otras redes:

```text
S1(config)# interface vlan 1
S1(config-if)# ip address 192.168.1.2 255.255.255.0
S1(config-if)# no shutdown
S1(config-if)# exit
S1(config)# ip default-gateway 192.168.1.1
```

## Acceso remoto con SSH

SSH cifra toda la sesión, incluidas las credenciales. Los pasos siempre son los mismos:

```text
R1(config)# ip domain-name ccna.lab
R1(config)# crypto key generate rsa general-keys modulus 2048
R1(config)# ip ssh version 2
R1(config)# username admin privilege 15 secret Admin#2026
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
```

1. **Hostname y dominio**: las llaves RSA se nombran con ellos, así que deben existir antes.
2. **Llaves RSA** de 2048 bits. Con menos de 768 bits no se puede usar SSH versión 2.
3. **Usuario local**: `login local` hace que las líneas VTY pidan usuario y contraseña de la base local.
4. **`transport input ssh`** rechaza Telnet en esas líneas.

En un switch las líneas VTY suelen ir de 0 a 15 (`line vty 0 15`). Para verificar:

```text
R1# show ip ssh
SSH Enabled - version 2.0
Authentication timeout: 120 secs; Authentication retries: 3
R1# show ssh
```

Desde una PC de Packet Tracer, en el **Command Prompt**: `ssh -l admin 192.168.1.1`.

<aside class="examen">

Memoriza el orden de los pasos de SSH y para qué sirve cada uno. Son frecuentes las preguntas de «¿qué falta en
esta configuración?», por ejemplo `login local` sin ningún `username` creado, o un switch sin `ip default-gateway`.

</aside>
